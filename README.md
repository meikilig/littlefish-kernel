# littlefish-kernel

一个「住在电脑里」的角色的**内核层**：人设卡、记忆卡、自我卡、二级开关、调度、预算账本、事件总线，以及一套读时推演的**疲劳 / 作息**模型。

它本身**不连 QQ、不调模型、不发消息**。它只负责「她是谁、记得什么、累不累、花了多少钱、这次该不该开口」，真正的通道、模型调用和平台行为都在配套的插件仓库里做：

> **插件仓库：[littlefish-plugins](https://github.com/meikilig/littlefish-plugins)**
> 内核不装插件就是一堆没人用的代码；插件不装内核起不来。两个仓库配套使用。

当前版本 **0.1.7**。

---

## 它是干什么的

一句话：**让一个大模型扮演的角色有连续的自我，而不是每次对话都从零开始。**

- 她有人设卡（不只是 system prompt，是可以在库里改版本的一条记录）；
- 她有记忆卡（重要度打分、召回、衰减，不是把所有历史塞进上下文）；
- 她有自我卡（自己那点小心思、今天想做的事）；
- 她知道自己累不累（精神值随作息推演，不是随机数）；
- 她知道这次调用花了多少钱（三档 token 分开记账）；
- 所有「开不开、能不能做」的开关有**唯一真相源**，界面、提示词、代码闸门读的是同一份。

## 架构

```
              ┌──────────── littlefish-plugins（另一个仓库）────────────┐
   QQ ──► SnowLuma ──► AstrBot ──► 插件层：通道 / 行为 / 各项能力       │
              └───────────────────────────┬────────────────────────────┘
                                          │ import littlefish_kernel
              ┌───────────────────────────▼────────────────────────────┐
              │  littlefish-kernel（本仓库）                           │
              │                                                        │
              │  persona  人设卡     memory  记忆卡     selfcard 自我卡 │
              │  vitals   疲劳/作息  budget  用量账本    think   内心话  │
              │  scheduler 调度      bus     事件总线    nightly 夜间整理│
              │  caps     二级开关   abilities 能力装卸  ops     运维    │
              │  db       SQLite     console 管理台 6197  desk/presence │
              └───────────────────────────┬────────────────────────────┘
                                          │
                        <ROOT>/data/persona/<角色>/littlefish.db
                        （唯一真相：所有状态都在这一个 SQLite 里）
```

**分层原则：内核往上不认识任何插件，插件往下才认识内核。** 拔掉插件，内核照样能跑、数据照样在；换掉内核，插件一行都不用改——只要接口还在。

### 模块一览

| 模块 | 干什么 |
| --- | --- |
| `persona.py` | 人设卡：库里是真相，`persona.md` 是编辑入口，带版本号 |
| `memory.py` | 记忆卡：写入时打重要度、召回时按需取，token 化检索 |
| `selfcard.py` | 自我卡：她的自我认知与当下状态 |
| `vitals.py` | **疲劳度**：精神值 + 生物钟，存两个数、读时推演，无 tick 线程 |
| `budget.py` | 用量账本：普通 / 缓存 / 输出三档分开计价，超限闸门 |
| `think.py` | 内心话（`data/think.jsonl`）：只记录，可随时整体删掉 |
| `scheduler.py` | 定时任务（APScheduler）：落盘、夜谈、备份 |
| `nightly.py` | 夜间整理：把今天的对话过一遍，写日记、挑该记的事 |
| `bus.py` | 事件总线：插件之间不直接互相调用，都发事件 |
| `caps.py` | **二级开关唯一真相源**：界面 / 工具面 / 提示词 / 代码闸门四处共读 |
| `abilities.py` | 能力装卸：装 = 往插件目录放代码，卸 = 挪进 `_removed/` 能装回去 |
| `ops.py` | 运维：体检、备份、日志、插件清单 |
| `console.py` | 管理台（127.0.0.1:6197，秘密路径当钥匙） |
| `db.py` | SQLite 连接与 schema（WAL，`SCHEMA_VERSION = 2`） |
| `config.py` | 一个根目录一份真相，所有路径从 `ROOT` 派生 |
| `desk.py` / `presence.py` | 在场状态：在不在、忙不忙 |
| `compat.py` | 兼容层：不同 AstrBot 版本的事件字段差异 |

## 疲劳度（vitals）

这是本仓库里最「自己发明」的一块，值得单独说。

**问题**：如果疲劳靠定时器每秒 tick，那关机十小时回来，她就还是关机那一刻的疲劳值；如果靠随机数，那「累」就没有意义。

**做法**：**只存两个数**——精神值 `vigor`，和这个数是什么时候算出来的 `at`。任何一次读都先用时间差按生物钟补算：

- 醒着的时候按每小时掉多少算；
- 到了睡眠时段按每小时回多少算，但有恢复上限（睡太久也不会无限满）；
- 中间醒来、午睡这种时段可以在配置里单独给速率。

所以没有后台线程、没有 tick 循环、不调模型；定时任务只是定期把结果落盘，顺便记一下睡/醒事件。**关掉十小时，开机第一次读就等于「照着生物钟过了十小时」。**

状态放在 `db.kv["vitals.state"]`，**不建表、不动 `SCHEMA_VERSION`**，升级零迁移风险。

还有一层保护：用量预算超限时是直接 `stop_event()` 把回复掐掉，角色会「哑掉」。所以「因为说得太快而累」用的是另一条路——`config.vitals.overload_yuan` / `overload_per_hour`（例如线上 8 元/小时），超了扣精神值，但话照说。

## 安装

```bash
pip install -e .
# 需要管理台（6197）时：
pip install -e ".[console]"
```

Python **3.10+**。依赖只有 `aiosqlite` 和 `apscheduler`。

## 配置

**没有 `config.json` 也能跑**——第一次启动会自动写一份默认配置。

数据根目录 `ROOT` 的确定顺序：

1. 环境变量 `LITTLEFISH_ROOT`；
2. 否则落在包目录外三级的 `littlefish/`（即 `<你放内核的目录>/littlefish`）。

首次启动会在 `ROOT` 下建 `data/`、`data/persona/`、`backups/`、`logs/`，并在 `ROOT/config.json` 写入默认配置。

常用环境变量：

| 变量 | 作用 |
| --- | --- |
| `LITTLEFISH_ROOT` | 数据根目录（人设、记忆、日记、账本都在这下面） |
| `LITTLEFISH_ASTRBOT_DIR` | AstrBot 安装目录（插件目录 / 插件配置目录从它派生） |
| `LITTLEFISH_PLUGINS_DIR` | 直接指定 AstrBot 插件目录 |
| `LITTLEFISH_PLUGIN_CONFIG_DIR` | 直接指定 AstrBot 插件配置目录 |
| `LITTLEFISH_SNOWLUMA_DIR` | SnowLuma 网关目录（管理台的「一键启动」用） |
| `LITTLEFISH_BILI_CLI` | B站 工具链入口（插件侧用） |

> 环境变量**每次现读**，不是 import 时读一次——这样测试里能临时改，线上也不受影响。

## 数据

一切都存在 `ROOT/data/persona/<角色>/littlefish.db` 一个 SQLite 里（WAL 模式）：人设卡、记忆卡、自我卡、用量、事件、键值。

**这个库里有人格、记忆和日记，是纯私人内容。** 本仓库不含任何这样的数据，`.gitignore` 也已经把它们排除在外；如果你的 `ROOT` 恰好落在仓库目录里，请务必确认 `data/` 没被提交。

管理台的管理路径密钥写在 `ROOT/data/console.token`，同样不入库。

## 和插件仓库的关系

| 本仓库 | 插件仓库 |
| --- | --- |
| 她是「谁」、记得什么、累不累、花了多少钱 | 她在 QQ 上怎么说话、怎么发消息、怎么用各项能力 |
| 唯一真相：一个 SQLite | 无状态或只用 `kv` 表存少量游标 |
| 不连任何平台 | 连接 SnowLuma / AstrBot / B站 等 |

插件通过 `import littlefish_kernel as lf` 使用内核；反过来内核**不 import 任何插件**，插件之间的耦合走 `bus.py` 的事件。

## 关于本项目的由来

本项目的基础功能**部分移植自 surfcore 项目**；在此之上的**「能力板块」**体系与**「疲劳度」**模型是后来自己设计实现的。

原项目与本项目的目标并不相同：原项目是一套偏「工具调用」的自动化框架，本项目想做的是一套让角色具有连续性自我的运行时。因此移植过来的一部分在语义上被重写了，能力板块、疲劳度、二级开关、能力装卸这些并不是原项目的东西。

详见 [NOTICE.md](NOTICE.md)。
